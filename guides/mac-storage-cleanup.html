맥 저장 공간이 부족할 때 먼저 확인할 폴더

2026년 11월 · YEOM HOJOON

256GB나 512GB 맥을 쓰다 보면 어느 날 "디스크가 거의 꽉 찼습니다"라는 알림을 보게 됩니다. 사진과 영상을 다루고 개발 도구까지 설치해 쓰는 입장에서 이 상황을 여러 번 겪었고, 그때마다 확인한 위치는 거의 비슷했습니다. 이 글은 무엇이 공간을 차지하는지 먼저 파악하고, 지워도 되는 것과 건드리면 안 되는 것을 구분해 안전하게 정리하는 순서를 정리한 것입니다.

정리를 시작하기 전에 Time Machine이나 외장 드라이브에 최신 백업이 있는지 먼저 확인하세요. 대부분의 캐시는 다시 만들어지지만, 실수로 지운 문서나 사진은 백업이 없으면 되돌리기 어렵습니다.

1. 먼저 사용량부터 확인하기

macOS Ventura 이후 버전에서는 시스템 설정 → 일반 → 저장 공간에서, 그 이전 버전에서는 이 Mac에 관하여 → 저장 공간 → 관리에서 사용량을 볼 수 있습니다. 응용 프로그램, 문서, 사진, 메시지, iOS 파일, 시스템 데이터처럼 범주별로 막대가 표시되고, 각 범주 옆의 정보 버튼(ⓘ)을 누르면 큰 파일 목록을 확인할 수 있습니다.

상단의 권장 사항도 한 번 살펴볼 만합니다. iCloud에 파일과 사진을 저장하고 기기에는 최근 항목만 남기는 기능, 30일이 지난 휴지통 항목을 자동으로 비우는 기능, 큰 파일과 오래된 다운로드를 검토하는 기능이 있습니다. 이 화면만으로 해결되는 경우도 꽤 많습니다.

계산에는 시간이 걸리므로 화면을 연 직후의 값은 정확하지 않을 수 있습니다. 또 Finder에 표시되는 "사용 가능" 용량에는 시스템이 필요할 때 자동으로 비우는 "제거 가능(purgeable)" 공간이 포함되어 있어, 저장 공간 화면의 수치와 조금 다르게 보이는 것이 정상입니다.

2. '시스템 데이터'가 큰 이유

많은 사람이 가장 당황하는 항목이 시스템 데이터입니다. 이름과 달리 macOS 자체만 들어 있는 것이 아니라, 다른 범주로 분류되지 않은 거의 모든 것이 이곳에 합산됩니다. 대표적으로 다음과 같은 것들이 포함됩니다.

  • 앱과 시스템이 만든 캐시, 로그 파일
  • Time Machine 로컬 스냅샷
  • Xcode의 빌드 데이터와 시뮬레이터
  • Docker, 가상 머신(Parallels, UTM 등)의 디스크 이미지
  • 메모리 부족 시 사용하는 스왑 파일과 잠자기 이미지
  • 앱이 ~/Library 아래에 저장하는 각종 데이터

그래서 시스템 데이터가 100GB를 넘었다고 해서 macOS에 문제가 생긴 것은 아닙니다. 아래 위치들을 차례로 확인하면 대부분 원인을 찾을 수 있습니다. 참고로 ~는 내 홈 폴더(/Users/사용자이름)를 뜻하고, Finder에서 ⌘⇧G(폴더로 이동)에 경로를 붙여 넣으면 바로 열 수 있습니다. ~/Library는 기본적으로 숨겨져 있어 이 방법이 가장 편합니다.

3. 용량을 많이 차지하는 위치와 정리 방법

위치무엇인가정리 방법과 주의점
~/Library/Caches브라우저, 디자인 툴, 메신저 등 앱이 빠르게 다시 쓰려고 저장한 임시 데이터대체로 안전합니다. 해당 앱을 종료한 뒤 하위 폴더 안의 내용을 지우면 다음 실행 때 다시 만들어집니다. 캐시 폴더 자체를 통째로 지우기보다 큰 앱 폴더 위주로 정리하세요.
~/Library/Developer/Xcode/DerivedDataXcode 빌드 중간 결과물안전합니다. 지우면 다음 빌드가 조금 오래 걸릴 뿐 자동으로 다시 생성됩니다.
~/Library/Developer/CoreSimulatoriOS 시뮬레이터 기기와 데이터직접 삭제하지 말고 터미널에서 xcrun simctl delete unavailable로 더 이상 쓸 수 없는 시뮬레이터를 지우세요. 안 쓰는 iOS 런타임은 Xcode 설정의 Platforms(Components) 항목에서 제거합니다.
~/Library/Developer/Xcode/Archives앱 배포용으로 만든 아카이브배포한 버전의 크래시 로그를 해석하려면 해당 아카이브의 dSYM이 필요합니다. 아직 지원 중인 버전은 남기고 오래된 것만 Xcode의 Organizer에서 지우세요.
~/Library/Developer/Xcode/iOS DeviceSupport연결했던 기기의 iOS 버전별 디버깅 심볼오래된 iOS 버전 폴더는 지워도 됩니다. 해당 기기를 다시 연결하면 필요한 만큼 다시 받습니다.
~/Library/Application Support/MobileSync/BackupFinder로 만든 iPhone·iPad 백업폴더를 직접 지우지 말고 Finder 사이드바에서 기기를 선택한 뒤 일반 → 백업 관리에서 오래된 백업을 삭제하세요. 저장 공간 화면의 iOS 파일 항목에서도 정리할 수 있습니다.
Docker Desktop 디스크 이미지이미지, 컨테이너, 볼륨, 빌드 캐시가 들어 있는 가상 디스크 파일 (Docker.raw)docker system df로 사용량을 먼저 확인하고 docker system prune으로 정리합니다. 디스크 파일을 직접 지우면 모든 컨테이너와 데이터가 사라집니다.
~/Downloads, 영상 파일설치 파일(.dmg, .pkg), 압축 파일, 촬영 원본 영상설치를 마친 .dmg와 이미 푼 압축 파일은 지워도 됩니다. 영상은 외장 드라이브로 옮긴 뒤 원본을 지우세요.
사진 보관함 (~/Pictures/Photos Library.photoslibrary)사진 앱의 모든 사진과 영상패키지 내부를 직접 건드리지 마세요. iCloud 사진을 쓰고 있다면 사진 → 설정 → iCloud에서 'Mac 저장 공간 최적화'를 켜면 원본은 iCloud에 두고 맥에는 작은 버전만 남깁니다.
오래된 프로젝트의 node_modulesJavaScript 프로젝트의 의존성 폴더안전합니다. 프로젝트 폴더에서 npm install 등으로 언제든 다시 설치할 수 있습니다. 프로젝트가 많다면 합쳐서 수십 GB가 되기도 합니다.
Time Machine 로컬 스냅샷백업 디스크가 연결되지 않았을 때 맥 안에 임시로 남기는 스냅샷tmutil listlocalsnapshots /로 목록을 볼 수 있습니다. 공간이 필요하면 macOS가 자동으로 지우므로 보통은 그대로 두어도 됩니다.
메일 첨부 파일메일 앱이 내려받은 첨부 파일과 메일 데이터메일 앱 설정의 일반 탭에서 편집하지 않은 다운로드 항목을 제거하는 시점을 정할 수 있습니다. ~/Library/Mail 폴더는 직접 지우지 마세요.
메시지 첨부 파일iMessage로 주고받은 사진, 영상, 파일메시지 → 설정 → 일반에서 메시지 보관 기간을 30일이나 1년으로 바꾸거나, 저장 공간 화면의 메시지 항목에서 큰 첨부 파일을 골라 지웁니다.

Docker는 옵션을 확인하고 정리하기

docker system prune은 중지된 컨테이너, 사용하지 않는 네트워크, 이름 없는(dangling) 이미지, 빌드 캐시를 지웁니다. 여기에 -a를 붙이면 실행 중인 컨테이너가 쓰지 않는 모든 이미지가 지워져 다음에 다시 내려받아야 하고, --volumes를 붙이면 데이터베이스 데이터처럼 볼륨에 저장된 내용까지 사라집니다. 로컬 개발용 DB 데이터를 볼륨에 두고 있다면 볼륨 옵션은 특히 조심하세요. 또 Docker.raw는 실제 사용량보다 크게 표시될 수 있는 파일이라, Finder에 보이는 크기와 실제로 차지하는 크기가 다를 수 있습니다. Docker Desktop 설정의 Resources 항목에서 가상 디스크 최대 크기를 줄일 수도 있습니다.

메시지와 iCloud 동기화에 주의하기

iCloud에 메시지 동기화를 켜 두었다면 맥에서 메시지나 첨부 파일을 지울 때 같은 Apple 계정을 쓰는 iPhone과 iPad에서도 함께 지워집니다. 사진 보관함도 iCloud 사진을 쓰는 경우 삭제가 모든 기기에 반영됩니다. 맥의 공간만 확보하고 싶다면 삭제보다는 저장 공간 최적화 옵션을 쓰는 것이 맞습니다.

그 밖에 확인해 볼 만한 곳

  • 패키지 관리자 캐시: Homebrew는 brew cleanup으로 오래된 버전과 내려받은 설치 파일을 정리할 수 있고, npm 캐시는 ~/.npm에 쌓입니다.
  • 가상 머신: Parallels나 UTM의 가상 디스크는 하나에 수십 GB가 흔합니다. 더 이상 쓰지 않는 가상 머신은 해당 앱 안에서 삭제하세요.
  • 영상 편집 앱의 캐시: Final Cut Pro의 렌더 파일, Premiere Pro와 DaVinci Resolve의 미디어 캐시는 각 앱의 메뉴에서 정리하는 것이 안전합니다.

4. 지우면 안 되는 것

용량을 줄이려다 시스템을 망가뜨리는 경우는 대부분 정체를 모르는 파일을 지웠을 때입니다. 다음은 건드리지 않는 것을 원칙으로 하세요.

  • /System 폴더: macOS 본체입니다. 최신 macOS는 이 영역을 읽기 전용으로 보호하므로 애초에 지울 수도 없고, 지울 이유도 없습니다.
  • /Library(홈 폴더가 아닌 최상위)의 시스템 파일: 드라이버, 시스템 확장, 공용 설정이 들어 있습니다. 앱을 지운 뒤 남은 폴더처럼 확실히 아는 것만 정리하세요.
  • 앱 번들의 내부: .app을 우클릭해 '패키지 내용 보기'로 연 뒤 언어 파일 등을 지우는 방법이 떠돌지만, 앱 서명이 깨져 실행되지 않을 수 있습니다.
  • 사진 보관함, 메일, 메시지의 내부 폴더: 데이터베이스와 파일이 서로 연결되어 있어 일부만 지우면 앱이 오류를 일으킵니다.
  • 무엇인지 확인할 수 없는 모든 것: 이름으로 검색해 봐도 확신이 서지 않는다면 지우지 않는 것이 맞습니다.
터미널의 rm 명령은 휴지통을 거치지 않고 바로 삭제합니다. 확신이 없을 때는 Finder에서 휴지통으로 옮겨 며칠 사용해 본 뒤 문제가 없으면 비우는 방식이 안전합니다.

5. 큰 폴더를 찾는 방법

Finder로 확인하기

폴더를 선택하고 ⌘I(정보 가져오기)를 누르면 폴더 전체 크기를 볼 수 있습니다. 목록 보기에서 보기 → 보기 옵션 보기의 '모든 크기 계산'을 켜면 하위 폴더 크기가 함께 표시되어 크기순으로 정렬할 수 있습니다. 숨김 파일은 ⌘⇧.로 보이게 할 수 있습니다.

터미널로 확인하기

여러 폴더의 크기를 한 번에 비교할 때는 du 명령이 빠릅니다. macOS의 du -sh는 각 항목의 총 크기(-s)를 읽기 쉬운 단위(-h)로 보여 줍니다.

  • 홈 폴더 아래 큰 항목 보기: du -sh ~/* 2>/dev/null | sort -h
  • Library 안에서 큰 폴더 20개: du -sh ~/Library/* 2>/dev/null | sort -h | tail -20
  • 숨김 폴더까지 포함하기: du -sh ~/.[!.]* 2>/dev/null | sort -h

sort -h는 KB, MB, GB 단위를 이해해 크기순으로 정렬하므로 가장 큰 항목이 맨 아래에 나옵니다. 실행하면 Operation not permitted나 Permission denied 같은 오류가 섞여 나올 수 있습니다. 메일, 메시지, Safari 데이터처럼 macOS가 개인정보 보호를 위해 접근을 막아 둔 폴더이거나 다른 사용자의 파일이기 때문입니다. 위 예시의 2>/dev/null은 이런 오류 메시지를 숨기는 부분이며, 그만큼 해당 폴더의 크기는 결과에서 빠진다는 점을 감안하면 됩니다. 크기를 확인하겠다고 sudo를 붙이거나 보안 설정을 바꿀 필요는 없습니다. 큰 폴더를 찾았다면 같은 명령을 그 폴더 안에 다시 실행해 한 단계씩 내려가면 됩니다.

여러 프로젝트에 흩어진 node_modules는 다음처럼 찾을 수 있습니다. 이 명령은 크기만 보여 주고 아무것도 지우지 않습니다.

find ~/Documents -name node_modules -type d -prune -exec du -sh {} + 2>/dev/null | sort -h

시각화 도구 사용하기

숫자 목록보다 그림으로 보는 편이 빠를 때도 있습니다. 이 사이트의 DiskMap은 폴더를 골라 큰 항목을 버블 지도로 보여 주는 읽기 전용 도구입니다. Chrome이나 Edge에서 File System Access API로 폴더를 읽기 때문에 파일이 업로드되지 않고, 아무것도 삭제하지 않습니다. 다만 브라우저는 보안상 ~/Library 같은 시스템 폴더를 폴더 선택 창에서 막아 두므로, 이런 경로까지 보고 싶다면 DiskMap 페이지에서 받을 수 있는 앱 버전을 이용하면 됩니다. 어떤 도구를 쓰든 무엇이 큰지 찾는 것까지가 도구의 몫이고, 지울지 말지는 위 표처럼 정체를 확인한 뒤 결정하는 것이 좋습니다.

6. 정리를 마친 뒤

  1. 휴지통 비우기: Finder에서 지운 파일은 휴지통을 비우기 전까지 공간을 그대로 차지합니다.
  2. 재시동하기: 재시동하면 스왑 파일과 임시 파일이 정리되고, 저장 공간 수치도 새로 계산됩니다.
  3. 잠시 후 다시 확인하기: 로컬 스냅샷이나 제거 가능 공간이 정리되는 데 시간이 걸려, 몇 분 뒤에 남은 용량이 더 늘어나는 경우도 있습니다.

정리가 끝났다면 같은 상황이 반복되지 않도록 휴지통 자동 비우기를 켜고, 사진과 영상 원본은 주기적으로 외장 드라이브로 옮기는 습관을 들이는 것을 권합니다.

자주 묻는 질문

캐시를 지우면 앱 설정이나 로그인 정보도 사라지나요?
~/Library/Caches의 내용은 다시 만들 수 있는 임시 데이터라 설정과 로그인 정보는 보통 유지됩니다. 설정은 ~/Library/Preferences, 앱 데이터는 ~/Library/Application Support에 따로 저장되므로 이 두 폴더는 함부로 지우지 마세요.
정리했는데 시스템 데이터가 줄지 않습니다.
휴지통을 비웠는지, 재시동했는지 먼저 확인하세요. 저장 공간 화면은 다시 계산하는 데 시간이 걸리고, 로컬 스냅샷이 지운 파일을 잠시 붙잡고 있을 수도 있습니다. 하루 정도 지난 뒤 다시 확인하면 줄어든 경우가 많습니다.
Time Machine 로컬 스냅샷을 직접 지워야 하나요?
보통은 그럴 필요가 없습니다. macOS는 공간이 부족해지면 오래된 로컬 스냅샷부터 자동으로 지웁니다. 큰 설치 작업 직전처럼 당장 공간이 필요할 때만 tmutil로 확인해 보세요.
저장 공간 정리 앱을 써도 괜찮나요?
무엇을 지우는지 목록으로 보여 주고 선택하게 하는 앱이라면 도움이 됩니다. 다만 '원클릭 최적화'처럼 무엇을 지우는지 알 수 없는 방식은 위에서 설명한 원칙에 맞지 않으므로 권하지 않습니다.
외장 SSD로 옮겨도 되는 것은 무엇인가요?
완성된 영상 프로젝트, 촬영 원본, 오래된 문서처럼 자주 쓰지 않는 파일이 가장 적합합니다. 사진 보관함도 사진 앱을 종료한 뒤 통째로 옮겨 열 수 있지만, iCloud 사진과 함께 쓸 때는 시스템 사진 보관함 설정을 확인해야 합니다.
